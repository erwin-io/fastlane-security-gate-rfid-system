Web Service (decides every tap)

The gate has no card list. Every tap is sent to POST /api/turnstile/tap and the barrier opens only when the server answers granted. No answer within the decision timeout = denied (fail-closed). A warm keep-alive connection is kept open so a tap costs a single request.

Gate Motor, Solenoid & Buzzer

Enable TB6600 gate motor
Invert TB6600 direction
Enable buzzer feedback
Solenoid behavior: Relay polarity is fixed ACTIVE-LOW for this machine: GPIO15 HIGH = LOCKED/OFF, GPIO15 LOW = UNLOCKED/ON. On GRANTED the solenoid unlocks immediately, then the NEMA motor waits a fixed minimum 1000 ms before OPEN movement starts. The configured solenoid hold time begins when the motor starts, so the lock stays released while the barrier begins moving. The return motor closes normally and the mechanical lock is expected to slide/re-catch automatically at the Closed Angle. The controller still assumes the physical gate starts at the Closed Angle because no home sensor is installed yet.

Simple Presence Status

v2.0.0: Both sensors range continuously in parallel while the gate is stopped and are paused while a motor moves. Presence is PRESENCE / NO_PRESENCE against a fixed calibrated background. RFID is disabled on PRESENCE and re-arms only when the gate is LOCKED and the lane has been clear continuously for the re-arm time.

Runtime Limits

Background = real distance (mm) to the far side of the empty lane. 0 = use the calibration file / saved capture. Offsets come from the multi-point calibration (S1 -43.375 mm, S2 -42.0 mm).
